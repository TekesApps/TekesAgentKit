# Frozen Run cancellation and Unknown consumer

This opt-in headless example targets the existing #55 Run lifecycle slice. It composes `SessionRuntime` and `RunController`; it introduces no parallel submission state machine or harness-private reads. The source baseline is frozen `5b7c84361206b45ac381b10437097d3b76c322c1`. Build only from an immutable stage archive with `--features acceptance-source-witness`; do not build on the live WIP checkout.

Configuration is one JSON object on stdin, bounded to 1 MiB. Credentials are supplied there and never printed. `kind` is `native`, `pi`, or `dsh`; connector fields follow `crates/headless/src/main.rs`. Optional `sessionId` selects an existing public session. Otherwise `cwd` creates one through the public session API. Optional `provider` and `model` explicitly select a model. `action` is `cancel` or `unknown`; both require a bounded fixture `prompt`. The independent provider/runtime owner must hold the matching unique prompt before these flows can prove a real in-flight mutation.

For `cancel`, use a unique fixture prompt and a nonempty `postPrepareDraft`. The consumer awaits the normal public dispatch, then waits until the same selected Run is actually cancellable. It records the original source witness, calls `RunController.cancel`, and waits for the same prompt's public Transcript turn to settle as `aborted`, with the source session closed and the Run no longer cancellable. An acknowledgement alone is insufficient. After emitting `run_cancellable`, the consumer waits for a new absolute `cancelSignal` file containing `cancel` (optional newline). The external provider fixture writes it only after it has entered this exact marked request and sent the first held stream frame. That removes the race where a cancellable Run appears just before the HTTP request reaches the provider. The provider fixture must independently prove it held exactly this request and no duplicate business request occurred. The bounded signal wait is 120 seconds and does not alter a harness RPC timeout. The output includes before/after public projection and same-memory authority; a stage validator binds call identity and cancellation source to the frozen runtime's contract.

For `unknown`, only Pi is supported by this slice. Provide an absolute `releaseSignal` path that does not exist. A transparent Pi stdio owner first passes setup RPCs, then arms its response gate at the exact marked official `prompt`. It withholds server-to-client bytes while preserving and draining them into bounded memory. The unchanged Pi RPC deadline must return through the original `RunController.dispatch`; the consumer records the original ticket as `unknown` and `reconciled=false`, edits a distinct nonempty parent draft, emits a JSONL `submission_unknown` record and waits for the external owner to write `release` (optionally followed by newline) to the signal file. The external runner releases the original buffered bytes through the same process generation. The consumer waits for the same ticket's automatic public reconciliation. If it stays unreconciled for 30 seconds, the consumer prints the final unknown receipt and exits with failure. It never reconnects into a new Pi process, acknowledges reconciliation manually, or dispatches the ticket again. The bounded external release wait is five minutes; it does not change the Pi RPC's 30-second deadline.

Output is JSONL: the Unknown phase record is flushed before waiting; final evidence is a separate line. Error text and credentials are not emitted. `RunSourceWitness` stores the exact immutable presentation publication together with its same-read `MemoryProjectionStore`; server-side transactional freshness is not asserted. An external validator must check original ticket, parent scope, source/call/result identity, provider request counts, process ownership, runtime version, and raw cancellation/receipt evidence before marking an applicable matrix cell accepted.

No real protocol run, binary, release gate, performance sample, UI, desktop, physical IME, or accessibility result is implied by this source file. Cancel is a cross-endpoint consumer path; Unknown is only Pi because its public receipt/reconciliation contract is endpoint-specific. If the selected frozen Pi build cannot emit a public reconciliation for the original ticket after the gated response is released, retain that failure and report it against #55; do not substitute matching prose, a reconnect into a new process, or a second dispatch.
