## Source guard review

- Task mounts use source generation plus weak owner identity and exact resolved scope (`ui/bindings/src/task.rs`). `begin` and source changes retire the old Run; `open_using` captures generation before I/O and checks it, the resolved scope, and parent access again before installation.
- Read-only child mounts inherit parent authority and recheck it after history reads. Their frames and read intents are tied to the original source/scope/publication/epoch; a retired mount loses action authority while retaining readable history (`ui/bindings/src/child.rs`). Custom child sources do not accidentally acquire endpoint pagination.
- Sidebar classification is provenance metadata, not a permission grant. Missing fields are not treated as main, and selected-row reads do not resurrect hidden child/ephemeral sessions. The current source revision and observer generation remain attached to the original publication.
- Composer and task callbacks carry their captured destination/source. Pane access is rechecked at admission; changing selected UI state does not redirect an already captured request. Unknown outcomes are reconciled explicitly and not automatically replayed.
- The SidePanel retirement implementation is an explicit additive host operation. It validates an opaque token against panel instance/context/projection/mount epoch and does not replace Task binding authority checks. The public consumer receipt exercises this new operation.

These are code-level findings from the frozen tree plus the linked receipts. No new runtime, desktop, IME, AX, Cargo, or protocol test was run for this review.
